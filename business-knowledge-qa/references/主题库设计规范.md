> **适用范围**：中心数仓 **DWT / DWS / ADS** 三层，包括所有以  
> `dwt_*`、`dws_*`、`ads_*` 命名的 Hive / ClickHouse / GaussDB 表及其 ETL 流程。

# 1. 核心层定位

| 层次 | 缩写 | 关键词 | 主要用途 |
|------|------|--------|----------|
| **DWT** | *Data Warehouse Topic* | **星型**、SCD、准实时 | 跨域复用的度量与维度基线 |
| **DWS** | *Data Warehouse Summary* | **宽表**、汇总、加速 | 场景导向的轻查询 / BI 自助、接口对接 |
| **ADS** | *Application Data Store* | **专题库**、大字段反向拉取 | 面向前端 / API 的最终数据交付 |

> **原则**：**先 DWT 后 DWS，最后 ADS**——  
> DWT 负责“正统模型 + 数据正确”，  
> DWS 负责“易用 + 高性能”，  
> ADS 负责“按需交付 + 最小依赖”。

---

# 2. 总则

1. **单域单库**  
   - `dwt_<domain>`、`dws_<domain>`；跨域宽表落 `dws_cross_<topic>`。  
2. **粒度不倒置**  
   - DWS 粒度 ≥（更粗于）DWT；ADS 只能等粒度或更粗，不得反向细化。  
3. **统一主键规则**  
   - 事实 / 桥接表主键 `pk_…`；维度 / 支架主键 `bk_…`；ADS 表继承来源层前缀。  
4. **分区统一**  
   - 默认 `dt STRING`（`yyyyMMdd`）；月分区 `yyyyMM`。  
5. **只读原则**  
   - 三层均禁 `UPDATE / DELETE`；需求变更走 **重跑** 或 **SCD**。  
6. **全量分区要求**  
   - 除 `dim_public` 外，所有 `dwt_<domain>` 表 **必须全量分区**；极小码表经评审可例外。  
7. **维度解耦**  
   - **实体维度 ↔ 实体维度** 禁直连，必须经 `bridge_…`。  
8. **ADS 链路**  
   - **常规**：仅从 DWS 取数 → 单向依赖；  
   - **例外**：可按白名单从 DWT / DWD **只读**拉大字段（正文、摘要等），详见 §5。

# 4. 分区策略

## 4.1 基础规则

| 库 | 分区原则 | 典型字段 |
|----|-----------|----------|
| `dim_public` | 可无分区（静态码表） | — |
| `dwt_<domain>` | **必须全量分区** | `dt` / `batch_id` |
| `dws_*` / `ads_*` | 业务驱动分区（快照 / 周期） | 业务日期、统计周期等 |

## 4.2 例外申请流程

1. **小体量码表**：提审 → 通过后免全量分区。  
2. **热点增量**：可在 DWT/DWS 侧引入 `is_current = 1` 视图遮罩减轻重跑。

# 6. DWT 事实表要点

1. **粒度声明** 写在 DDL 注释首行。  
2. 主键 `pk_*` 支持幂等加载。  
3. 指标列可标 `/* additive */` / `/* non-additive */`。  
4. 大文本移至 **1:1 维表** 或外部索引。  
5. 默认分区 `dt = yyyyMMdd`；若粒度 < 日，可加二级目录。

# 8. 变更治理

1. **变更分类**：模型新增 / 字段扩展 / 粒度调整 / 分区变更 …  
2. **版本号**：`ddl_version` 写在表注释尾行并打 Git Tag。  
3. **豁免流程**：特殊需求走“模型豁免申请”并归档。

# 9. 常规反模式

| 反模式 | 风险 |
|---|---|
| 把正文塞入 Fact / DWS / ADS 宽表 | IO 抖动、存储膨胀 |
| DWT 星型未验主键唯一 | 聚合双算 / 漏算 |
| DWS / ADS 跨域宽表无粒度声明 | 全表扫爆炸、不可维护 |
| 小文件海量分区 | NameNode 压力、Task 爆炸 |

# 10. 其他补充规范
1**字段注释**：DDL 必带 `COMMENT`，缺失拒绝上线。  
2**数据类型基线**  
   - 字符串用 `STRING`；  
   - 金额 / 指标统一 `DECIMAL(18,4)`。  
3**生命周期**：分区表配置保留策略（默认7天(或3月)自动归档）。  
4**表级元数据**：`COMMENT` 首行业务含义，次行 `owner=xxx;domain=yyy`。
5**版本控制**：DDL 改动走 Git MR；CI 执行 `schemachange --dry-run`。（后续执行）
6**质量校验**：每日调度后跑行数 & HASH 校验写监控表。
